换一个 Agent，
也能接上之前的事。

MemHub 把长期知识、任务进度和聊天记录保存在本地，让不同 AI 助手通过同一套接口读取。宿主负责接入，核心负责组织记忆；自动续聊的完成度取决于各宿主的接入进度。

聊天记录

演示按默认期限、活跃条目和整天时间计算。实际会话过期以毫秒差值为准，必须超过期限。拖动滑块不会操作真实文件。

“不再自动读取”不等于删除

过期聊天仍可显式加载。指定父会话可以绕过自动选源的期限过滤；本次会话已选定的恢复来源也会保持固定。旧内容不会从模型已经收到的上下文里撤回。

真正删除是另一个动作

没有定时清除聊天的任务。session prune 默认只预览，加 --confirm 才删除当前工作区超期的 MemHub 会话副本。长期条目物理删除也需要明确确认；不会删除宿主自己的聊天历史。

05 / CURRENT BOUNDARIES

现在能做到哪里？

代码支持、接入方式与真实宿主验收，是三件不同的事。

入口长期记忆 / 任务交接完整聊天的自动采集与续聊当前边界
PI-Desktop插件自动注入 + 主动工具0.3.4 已有事件实现请求前保存、轮次结束落盘、空闲后自检、新会话恢复真实桌面双窗口验收待完成已具备扩展事件与宿主加载器测试；未核验当前安装版本
Claude CodeHooks + MCP启动、提问、工具事件、Stop 自检完整 transcript 接入待完成长期记忆 Hook 已有代码Stop 自检只补长期记忆，不等于统一会话完整采集
Codex / Cursor / Pi CLIMCP + Skill由 Agent 主动调用记忆及会话工具自动流程未完成当前不提供已验收的原生自动 HookCodex CLI 与桌面端需分别验证
其他宿主 / DSH共享文件作为兜底也可按实际 MCP 能力接入需按宿主核实不由文件兼容推断自动续聊已支持
CLI / Web检索、浏览、审批、SOUL 与归档管理CLI 提供独立会话命令Web 目前主要管理长期记忆和 Inbox管理入口，不负责捕获其他宿主的事件

模型只做可选辅助

rerank：从候选标头挑相关记忆，失败退回关键词。summary：压缩会话供恢复，自动保存摘要，不写长期记忆。记忆提炼由当前 Agent 每轮自检完成，不再单独调用复盘模型。未完整配置 URL 和模型的通道不启用。

本地规则负责确定行为

目录归属、过期判断、状态过滤、去重和确认后删除由代码执行。没有让后台模型持续遍历旧记忆并自动淘汰的机制；冷记忆超过 90 天未访问时，检查工具仅建议归档。已知密钥格式会过滤，不能据此视为完整脱敏。

基础存储在本地；开启模型通道后，相应的提问、候选标头或过滤后的对话会发送到所配置的端点。本页只展示代码结构，不读取本机密钥、聊天或服务状态。

依据当前仓库代码核对（0.3.4 每轮自检版本）。参考：README · 会话层设计 · 实施与验收记录。历史文档部分仍标注旧版本，本页以当前代码为准。
