# 会话记忆第一阶段实施与验证

状态：设计第 1–3 步已具备核心实现和 PI 扩展事件测试；真实 PI 桌面端双窗口验收未执行，整套跨宿主方案尚未完成。插件版本 0.3.0，测试环境 Node.js v24.14.1（macOS）。没有修改本机宿主配置，没有批量导入既有聊天。

## 已实现

- 统一 `captureSession`、`restoreSessionContext`、`listSessions`、`loadSession`、`summarizeSession`，以及 `sessionDiagnostics`、`rebuildSessionLocations`。
- 工作区使用规范化的真实路径，项目沿用现有根目录判定，不同 worktree 分别恢复；非项目记录保存在全局 sessions 下，按实际目录过滤。
- 每个会话使用工作区、Agent、宿主会话 ID 的 SHA-256 键保存到独立目录，稳定消息 ID 去重、毫秒时间和连续序号。临时内容标识可在宿主随后提供稳定 ID 时合并；无稳定标识的缺口有诊断。
- `turns.jsonl` 是原子替换的权威日志：首行为 `record_type="metadata"` 的元信息与摘要，其余每行为标准化消息。元信息包含 `schema_version=1`。完整日志和 Markdown 快照在事务内先后写入；读取时从日志重建快照。当前实现每次重写完整会话，未做大日志的分段与流式优化，不限制保存总量。
- `sessions/.gitignore` 保留原规则，并在末尾补充排除规则。长期目录、搜索、Inbox 和 doctor 的长期条目统计均不包含会话。
- PI 在 `before_provider_request` 保存能取得的消息，`agent_end` 等待基础落盘，关闭时补存；基础保存独立于长期复盘和摘要模型。启动通过与 MCP 相同的恢复函数生成 `<memory-session>`。
- 最近来源固定到 `restored_from`；优先显式父会话，默认排除子代理；没有来源也固定为空，不因其他窗口后来发言而更换。
- 摘要使用独立 `summary` 配置，网络等待不持写锁；按完整消息的实际范围推进，晚返回的旧摘要不能覆盖已推进的摘要。失败保留原文与覆盖范围，结果不进入长期 Inbox。
- 跨工作区索引只保存定位，不保存正文。索引写失败不回滚本地对话；显式 `session rebuild` 可从已知目录重建。
- MCP 增加 5 个 `memory_session_*` 工具，PI 对应 5 个 `session_*` 工具，CLI 增加 `session` 命令和 doctor 状态。

## 已执行的验证

`npm test`：41/41 通过（原有 29 项，加 12 项会话测试）；`git diff --check` 通过。模型返回使用受控测试响应，未向真实外部模型发送测试对话。

| 场景 | 测试来源、序号与观察结果 |
| --- | --- |
| PI 旧窗口不关闭立即新开 | 扩展事件模拟：A 在请求前保存 #1，`agent_end` 合并宿主时间戳并保存到 #2；B 启动块包含 A 的用户话语与未确认的助手建议，来源为 `pi-desktop` |
| 跨 Agent 统一读取 | 核心调用：PI A 保存 #1–#2，`claude-code` B 恢复 A；MCP `memory_boot` 的 `codex` 来源也能恢复统一记录。只证明共享协议，未验证真实宿主自动事件 |
| 来源稳定与父会话 | B 选择 A 后，C 更新不改变 B 的来源；指定 A 为父会话时优先 A；新的子代理记录不参与默认上一主会话选择 |
| 工作区归属 | A 对话保存在 A，B 默认看不到 A；显式跨工作区发现与指定目标工作区加载可读取 A；两个非项目目录相互隔离。现有跨项目 handoff 测试继续通过 |
| 摘要等待与失败 | #1–#2 摘要等待时追加 #3，新会话立即读到 #3；摘要返回只覆盖到 #2，状态保持 pending；关闭、请求失败、无效 JSON 均不丢原话 |
| 摘要乱序与范围 | 旧请求覆盖 #1，新请求覆盖 #1–#2；新摘要先提交后，旧请求返回 stale。预算不足时只推进实际完整处理的序号，超长消息标失败而不假装覆盖 |
| 重复事件与并发 | 同一完整 transcript 并发提交 5 次仍只有 #1–#2；相同文本有不同稳定 ID 时保留为 #3。4 个独立 CLI 进程写同一会话，最终 #1–#4 全部存在 |
| 中断快照与长原文 | 人为写入过时 Markdown 后，从日志恢复正确快照；30 万字符原话完整读取，启动块明确标记裁剪 |
| 注入、敏感内容与角色 | 已知测试 API Key 被过滤，memory 注入块不回流，thinking 块被排除；工具调用/结果单独标记 tool，图片只保存引用，不保存 data URI 二进制 |
| 权限与定位故障 | 路径穿越、符号链接会被拒绝；索引损坏时仍能本地保存和恢复，状态为 failed，可显式重建。诊断不输出对话正文 |
| 插件打包 | `PluginCheck` 通过；`PluginPack` 生成 14 文件安装包。入口能加载 4 个原有工具和 5 个会话工具 |

安装包由 `PluginPack` 生成于 `build/pi-desktop-0.3.0/dist/memhub.universal-memory-0.3.0.piplug`，SHA-256：`b8f96ad9138228c97c41806a22aac7b8105af8aa5a8340390cc5a1ff31163fd3`。校验提示宿主需授予原有的 `agent.tool.register`、`agent.extension`、`net.fetch` 权限，并指出允许访问 localhost；没有通过这次打包自动授权或安装。
